Membuat CRUD Pendaftaran Siswa Baru dengan PHP dan MySQL: RuangSiswa

Pada tugas kali ini, saya membuat RuangSiswa, aplikasi pendaftaran siswa baru yang menerapkan empat operasi dasar pengelolaan data: Create, Read, Update, dan Delete. Proyek ini mengikuti materi CRUD 2 Pendaftaran Siswa Baru dari Fajar Baskoro.

Aplikasi menyediakan halaman ringkasan, formulir pendaftaran, daftar siswa, detail, edit, serta konfirmasi penghapusan. Saya menambahkan pencarian, filter jenis kelamin, dan paginasi supaya data lebih mudah diperiksa. Seluruh contoh nama dan sekolah merupakan data fiktif untuk latihan.

Buka demo RuangSiswa · Source code di GitHub

1. Memahami Alur CRUD

Create terjadi ketika pengguna mengisi formulir lalu menyimpan pendaftaran. Read digunakan untuk menampilkan daftar dan detail siswa. Update memperbarui data melalui formulir edit. Delete menghapus satu pendaftaran setelah pengguna memberikan konfirmasi pada halaman khusus.

Setiap perubahan yang berhasil diikuti redirect dan pesan hasil. Dengan pola Post/Redirect/Get, memuat ulang halaman tujuan tidak langsung mengirim formulir tambah sekali lagi. JavaScript hanya membantu navigasi ponsel dan fokus pada kolom yang bermasalah. Pengelolaan data tetap berjalan melalui formulir HTML dan PHP.

2. Menyusun Database Pendaftaran

Materi menggunakan database pendaftaran_siswa dan tabel calon_siswa. Data utamanya adalah id, nama, alamat, jenis_kelamin, agama, dan sekolah_asal. ID menjadi primary key dengan auto increment.

Implementasi saya menambahkan workspace_id untuk memisahkan ruang demo antar browser serta created_at untuk mencatat waktu pendaftaran. Kedua kolom ini merupakan tambahan teknis pada proyek, sedangkan lima isian formulir tetap mengikuti materi.

CREATE TABLE calon_siswa (
    id INT NOT NULL AUTO_INCREMENT,
    workspace_id CHAR(32) NOT NULL,
    nama VARCHAR(64) NOT NULL,
    alamat VARCHAR(255) NOT NULL,
    jenis_kelamin VARCHAR(16) NOT NULL,
    agama VARCHAR(16) NOT NULL,
    sekolah_asal VARCHAR(64) NOT NULL,
    created_at DATETIME NOT NULL,
    PRIMARY KEY (id),
    INDEX siswa_workspace (workspace_id, id)
);

Nama dan sekolah asal dibatasi 64 karakter, sedangkan alamat maksimal 255 karakter. Pilihan jenis kelamin dan agama diperiksa kembali di server. Jadi, mengubah pilihan formulir melalui browser tidak membuat nilai di luar daftar langsung diterima.

3. Membagi Tanggung Jawab Setiap File

File config.php memuat bootstrap aplikasi. Koneksi database dikelola melalui app/database.php. Fungsi layout dan formulir disimpan pada folder app/ agar halaman tambah dan edit menggunakan aturan tampilan yang sama.

  • index.php: ringkasan jumlah pendaftar dan siswa terbaru.
  • form-daftar.php: formulir lima informasi utama siswa.
  • proses-pendaftaran.php: validasi dan query INSERT.
  • list-siswa.php: daftar, pencarian, filter, dan paginasi.
  • detail.php: seluruh informasi seorang calon siswa.
  • form-edit.php dan proses-edit.php: menampilkan serta menyimpan perubahan.
  • hapus.php: konfirmasi pada GET dan penghapusan pada POST.

Document root diarahkan ke folder public/. Konfigurasi, database, dan penyimpanan lokal berada di luar folder publik. Pada deployment Vercel, router hanya mengizinkan nama halaman yang telah ditentukan.

4. Menghubungkan PHP dengan MySQL

Saya menggunakan PDO untuk menghubungkan PHP dengan MySQL. Host, port, database, username, dan password dibaca dari environment. Repository menyediakan .env.example, sedangkan konfigurasi asli tidak ikut diunggah ke GitHub.

$query = db()->prepare(
    'UPDATE calon_siswa
     SET nama=?, alamat=?, jenis_kelamin=?, agama=?, sekolah_asal=?
     WHERE id=? AND workspace_id=?'
);
$query->execute([
    $data['nama'], $data['alamat'], $data['jenis_kelamin'],
    $data['agama'], $data['sekolah_asal'], $id,
    $_SESSION['workspace']
]);

Nilai pengguna dikirim melalui parameter, terpisah dari teks SQL. Kondisi workspace_id diterapkan pada pembacaan, perubahan, dan penghapusan. Mengganti ID pada URL tidak memberikan akses ke data milik ruang demo lain.

5. Validasi dan Penghapusan yang Terarah

Validasi server memeriksa panjang teks, kolom wajib, serta pilihan yang diizinkan. Jika ada kesalahan, formulir menampilkan pesan di dekat kolom dan mempertahankan isian sebelumnya. Nilai yang ditampilkan kembali menggunakan htmlspecialchars sehingga input berupa tag HTML tampil sebagai teks.

Semua perubahan data memerlukan POST dan token CSRF yang sesuai sesi. Membuka tautan hapus hanya menampilkan pertanyaan konfirmasi. Pengguna bisa kembali ke detail melalui tombol Batal. DELETE baru dijalankan ketika formulir konfirmasi dikirim dan tokennya valid.

Ruang demo dibatasi maksimal 100 siswa dan diawali enam data fiktif. Menghapus semua siswa tidak memuat ulang data contoh. Pemisahan sesi ini ditujukan untuk latihan bersama, bukan pengganti autentikasi akun petugas sekolah.

6. Menjalankan Lokal dan Mendeploy

Untuk mencoba lokal, gunakan PHP 8.2 atau lebih baru dengan PDO, pdo_sqlite, dan mbstring, lalu jalankan php -S localhost:8000 -t public. Aplikasi secara default membuat SQLite di folder storage/. Jika ingin mengikuti latihan MySQL, impor database/mysql.sql, salin .env.example menjadi .env, dan ubah DB_DRIVER=mysql.

Demo online di Vercel menggunakan PHP dan SQLite dengan snapshot pada Vercel Blob privat. MySQL merupakan pilihan implementasi lokal; demo online tidak diklaim menggunakan MySQL. Penyimpanan Blob diperlukan karena file sementara pada fungsi serverless tidak dapat dijadikan penyimpanan permanen.

Setelah perubahan berhasil, snapshot database dan sesi disimpan sebelum redirect sukses. Request berikutnya mengambil snapshot terbaru. ETag digunakan agar dua perubahan bersamaan tidak saling menimpa tanpa diketahui. Data demo disimpan dengan masa berlaku tujuh hari; menghapus cookie akan membuka ruang baru.

7. Pengujian dan Hasil Pembelajaran

Pengujian HTTP disediakan di folder tests/ untuk memeriksa tambah, baca, edit, hapus, pencarian, filter, validasi, token CSRF, dan isolasi antar sesi. Pengujian database lokal menggunakan SQLite dan MySQL/MariaDB. Demo produksi juga diperiksa dengan data fiktif pada sesi uji sendiri. Rincian hasil disimpan pada file laporan QA di repository.

Pemeriksaan visual melalui browser otomatis belum dapat dilakukan karena akses browser pengujian di lingkungan kerja tidak tersedia. Layout menggunakan CSS responsif, tabel dengan area gulir, label formulir yang terlihat, fokus keyboard, dan navigasi ponsel. Pemeriksaan HTTP tidak menggantikan peninjauan visual langsung.

Melalui proyek ini, saya mempelajari hubungan antara formulir HTML, validasi PHP, query berparameter, dan penyimpanan database. CRUD juga melatih penanganan keadaan kosong, data yang sudah dihapus, dan kegagalan penyimpanan agar hasil aplikasi tetap dapat dipahami pengguna.
